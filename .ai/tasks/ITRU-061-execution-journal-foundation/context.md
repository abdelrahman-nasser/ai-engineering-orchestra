## Locked decisions and investigation

The canonical specification owns the proposed Journal semantics. It proposes a
separate provisioned local SQLite Journal, independent of the existing v4
authorization ledger. This avoids changing immutable migrations, Entry triggers,
watermark or authorization consumption. Neither an ordinary JSONL file nor a
co-located new Admission-ledger table provides an approved substitute.

Two event kinds suffice: `entry_observed` and `result_observed`. Normal recording
occurs after original execution/Result publication and S/G/P/W/C scopes unwind.
An atomic Journal batch records the Entry and content-free Result summary.
The Journal is authoritative for accepted historical observations under its trusted
writer/storage boundary; the ledger remains authoritative for Entry/authority,
and the original Result remains authoritative for its immutable terminal outcome.

There is deliberately no atomic transaction spanning native effect, Entry ledger,
live Result publication and Journal. Missing history remains detectable unresolved
evidence. Journal storage failure cannot change a Result or enable replay. The
caller receives separate Journal durability evidence; complete Journal coverage is
never inferred. Restart can retrieve summaries and reconcile committed Entries,
but cannot reconstruct a genuine Result or recover a continuation.

The current coordinator history call needs the old Claim/executor context. Phase 2
must add a narrowly audited passive ledger-history read seam, using exact pinned
ledger and stored subject values, without reconstructing an old capability. Its
implementation and lock order must be independently reviewed before execution.
This is a known implementation requirement, not a Phase-1 code change.
